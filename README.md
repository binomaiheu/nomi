NoMi - a little SFML platformer for educating myself and hopefully someday my kids too ;-)
(c) 2019 Bino Maiheu

Run, jump and stomp through levels made with the [Tiled](https://www.mapeditor.org) map editor.
Pick your hero (Kit, Gnu, Tux, Wilber or Kisi), collect coins and reach the flag.

# Playing

| Key                    | Action                                     |
|------------------------|--------------------------------------------|
| ← → (or A D)           | walk                                       |
| Space (or ↑, W)        | jump : tap for a small hop, hold to jump high |
| Esc / P                | pause (Q in the pause menu goes back to the title) |
| M                      | mute music and sounds                      |
| F1                     | show collision boxes                       |

A gamepad works too (stick or d-pad to walk, A to jump, Start to pause).

Land on an enemy to stomp it (hold jump while stomping for a big bounce); touching one any
other way, or falling into a pit, costs a life. Every 100 coins give an extra life.

Command line options :

```
nomi --level share/levels/level2.tmx   # start directly in a level
nomi --debug                           # draw collision boxes
nomi --autotest [--level file]         # headless bot playthrough, exit code 0 when it reaches the flag
```

# Building

Needs CMake 3.21+, a C++17 compiler and [vcpkg](https://vcpkg.io). The libraries (SFML 3, tmxlite,
doctest) are declared in `vcpkg.json` and built automatically on the first configure.

vcpkg is found through `CMAKE_TOOLCHAIN_FILE`, the `VCPKG_ROOT` environment variable, or a `vcpkg`
checkout next to this project (`../vcpkg`).

On Windows with Visual Studio 2022 or newer (or its Build Tools) :

```
cmake --preset windows
cmake --build --preset release
build\Release\nomi.exe
```

Run the tests (unit tests, level validation and a bot playthrough of every level) with

```
cmake --build --preset debug
ctest --preset debug
```

# Packaging and releasing

The release build links everything statically into a single `nomi.exe` (no console window) and
packs it with the `share/` assets into a ZIP and an installer (NSIS, with start menu and desktop
shortcuts and an uninstaller) :

```
cmake --preset windows-static
cmake --build --preset package
cpack --preset package            # -> build-static/nomi-<version>-win64.zip / .exe
```

The installer needs [NSIS](https://nsis.sourceforge.io) (`winget install NSIS.NSIS`).

To publish a release on GitHub, bump the version in `CMakeLists.txt` (`project(nomi VERSION x.y.z)`),
commit, and push a matching tag :

```
git tag v1.0.0
git push origin v1.0.0
```

The GitHub Actions workflow (`.github/workflows/build.yml`) builds, tests and packages every push,
and for a `v*` tag it creates the release with the ZIP and installer attached. The installer is not
code-signed, so Windows SmartScreen shows a warning the first time ("More info" -> "Run anyway").

# Making levels with Tiled

Open `share/levels/nomi.tiled-project` in Tiled, then open or create a map in `share/levels`.
Press F5 in Tiled ("Play in nomi") to save and play the map straight away.

A map uses 64x64 tiles and these layers :

| Layer                 | Type    | Purpose |
|-----------------------|---------|---------|
| `Backdrop`            | tiles   | far away hills from `backdrop.tsx`, give it a parallax factor (e.g. 0.35) in the layer properties |
| `Decoration`          | tiles   | trees, fences, flowers, water ... (no collision) |
| `Ground`              | tiles   | the terrain you walk on. Every tile here is solid, except tiles with the property `oneway` (the stone slabs) which you can jump through from below |
| `Foreground...`       | tiles   | any tile layer whose name starts with `Foreground` is drawn in front of the characters |
| `solids`              | objects | extra invisible solid rectangles |
| `entities`            | objects | the things in the level, placed as tiles from `entities.tsx` |

Entities (drag them from the `entities` tileset onto the `entities` layer) :

* **spawn** (the fox) : where the player starts, exactly one per level
* **coin**
* **enemy** : walks back and forth and turns at walls and ledges. Properties `sprite` (gnu, tux, wilber or kisi)
  and `speed` (pixels per second) - pick the enemy tile you like, or change the properties on the object
* **goal** : the finish flag

Map properties : `name` is shown when the level starts, `next` is the file of the following level
(the last level has no `next`). The map background colour is the sky colour.

The levels shipped with the game are generated by `tools/gen_level.py`, which also checks that every
gap can be jumped with the game's physics. You can edit the generated `.tmx` files in Tiled directly,
but re-running the script overwrites them, so save hand-made levels under a new name.
